# Sider v0.1.0

Historical draft from preparation that ended without publication. The current
workflow uses milestone 0.1 as an internal checkpoint and publishes only 1.0.
The content below records the earlier proposal, not instructions to publish another
0.1 version. Records from `v0.1.0-rc.1` remain evidence only for that revision.

First functional version of Sider, an in-memory database server written in Rust.
For experimental use in a controlled environment. This version provides neither
persistence nor authentication and must not be exposed to the internet.

## Delivered

- Incremental RESP2/TCP: `PING [message]`, `ECHO message`, `GET key`,
  basic `SET key value`, and `DEL key [key ...]`.
- Binary keys and values, including empty values, NUL, and non-UTF-8 bytes.
  Command names are ASCII case-insensitive; keys distinguish every byte.
- Multiple connections, pipelines ordered per connection, one owning worker,
  a bounded queue, protocol limits, and configurable timeouts.
- `--help`/`--version` CLI, `SIDER_*` configuration, optional file-based readiness,
  and supervised shutdown.
- Native Linux/Windows tests, comparison with Redis and redis-cli 8.10.1,
  and smoke tests of extracted executables.

## Installing and trying it

Download the package for your system and `SHA256SUMS`, verify its hash, and extract
the archive. Rust and Cargo are not required to run the server.

- Linux x86_64 GNU: `.tar.gz` package, built and tested on Ubuntu 24.04.
  From the extracted directory, run `./sider --version` and `./sider`.
- Windows x86_64 MSVC: `.zip` package. In PowerShell, from the extracted directory,
  run `.\sider.exe --version` and `.\sider.exe`.
  Requires the [Visual C++ v14 Redistributable x64](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist),
  installed separately; `VCRUNTIME140.dll` is not included in the ZIP.

The default address is `127.0.0.1:6379`. Use Ctrl+C to stop. In another terminal,
with redis-cli installed separately:

```sh
redis-cli -2 -h 127.0.0.1 -p 6379 PING
redis-cli -2 -h 127.0.0.1 -p 6379 SET example value
redis-cli -2 -h 127.0.0.1 -p 6379 GET example
redis-cli -2 -h 127.0.0.1 -p 6379 DEL example
```

## Contracts and limitations

There is no TTL, dataset quota, eviction, persistence, replication, or collection
types. All data is lost when the process ends. Writes can exhaust memory even
while respecting network limits.

The protocol accepts only nonempty arrays of non-null bulk strings.
There are no inline commands, RESP3, `SELECT`, `AUTH`, `HELLO`, `CLIENT`, or
`COMMAND`. Clients that require these initialization commands may not work.
Additional `SET` options return `ERR unsupported SET options`, without mutation.
`ERR unknown command` uses simplified text. Invalid framing, formats outside
the subset, and exceeded limits close the connection.

Defaults allow 32 connections and 32 commands waiting for the worker, 1 MiB bulk
strings, 4 MiB frames/input buffers/responses, 1,024-byte lines, 1,024 nodes, and
depth 16. Timeouts are 10 seconds to form a frame and 5 seconds for response waiting,
writing, and draining. Idle connections do not expire.

After a command enters the worker queue, a timeout or disconnection may leave the
outcome unknown to the client. There is no automatic retry or rollback.
Draining is cooperative and provides neither durability nor guarantees after forced
termination. There is no TLS or ACL; binding outside loopback only emits a warning.

## Validation and artifacts

Publication uses the exact release PR merge SHA, with local validation and no CI.
`release-manifest.json` records the SHA, tools, targets, commands, and results.
Receipts and logs must distinguish native tests, compatibility, and smoke tests of
extracted packages. Implementation or candidate results do not replace this final
release's gates.

The reference is Redis and redis-cli 8.10.1, Linux amd64, pinned by digest in
[this version's manifest](https://github.com/djairofilho/sider/blob/v0.1.0/releases/plan.json).
There is no claim of full Redis compatibility or a goal of outperforming it.

See the [compatibility matrix](https://github.com/djairofilho/sider/blob/v0.1.0/docs/compatibility.md),
[network guide](https://github.com/djairofilho/sider/blob/v0.1.0/docs/network.md),
and [testing guide](https://github.com/djairofilho/sider/blob/v0.1.0/docs/testing.md).

Project code uses the MIT license. The repository and artifacts remain private;
there is no crates.io publication. This final release requires an approved candidate
of the same base version, with no subsequent functional changes, and a new build
and validation. Approval and results for both are recorded in the publication issue.

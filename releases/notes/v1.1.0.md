# Sider 1.1.0

Sider 1.1.0 adds the capabilities developed after 1.0.1 in one Linux amd64
Docker image. The public runtime distribution is
`ghcr.io/djairofilho/sider`; the approved OCI digest, exact source SHA, and
validation receipts belong to the candidate release record. This note does not
declare a candidate or final release published.

## Capabilities

- The 1.0.1 command and storage base remains available.
- `MEM.*` supports binary-safe collection lifecycle, members, exact search,
  backup, migration, and replication in the record-2 memory profile.
- `HELLO 2` and `HELLO 3` negotiate the implemented RESP2/RESP3 subset.
- Protected startup requires client TLS, named authentication, and ACLs.
  Separate internal TLS identities authorize backup, replication, monitoring,
  and promotion operations.
- Mixed-owner `MULTI`/`EXEC` uses a single durable decision and complete-record
  recovery in the record-1 composed profile.

## Deployment contract

The memory and composed profiles use **different persistent volumes**. The
image refuses a volume created for the other profile. One instance cannot run
both durable formats together. The default protected profile requires restricted
security material before listeners or recovery become ready; it never falls
back to plaintext. The [Docker launch guide](../../docs/docker-first-launch.md)
provides provisioning, Compose commands, backup and restore, rotation, and
separate profile examples.

The release is distributed through the public Linux amd64 image only. Native
Linux builds and tests remain development and validation tools; no native Linux
or Windows package is a 1.1.0 release asset. The 1.0.1 package and image paths
remain historical.

## Compatibility and limits

The supported RESP3 behavior is the documented command and response subset;
this release does not claim complete Redis compatibility. Replication is
asynchronous, promotion is manual, and cross-shard transactions involve local
shards in the explicit composed profile. Lua, cluster topology, automatic
failover, and online resharding are outside this release. See the
[compatibility matrix](../../docs/compatibility.md) and the
[transaction contract](../../docs/cross-shard-transactions.md).

## Candidate approval

The candidate must pass all R13 gates on the exact source SHA and public image
pulled by OCI digest, including protected container behavior, both durable
profiles, backup and replication, a continuous 3600-second soak, and an isolated
benchmark. Missing or failed evidence blocks publication. After approval,
`1.1.0` must resolve to the same digest as `1.1.0-rc.1`, without rebuilding.
The [release process](../../docs/releases.md) defines the manual checks.
